# PageWatcher Mobile

The Flutter (Android + iOS) client for [PageWatcher](https://pagewatcher.app). All page checking, diffing, AI filtering and notifications run on the existing FastAPI backend (`../pagewatcher`). The app is a native client of its REST API at `/api/v1`.

## First-time setup

The source is ready, but the `android/` and `ios/` folders are generated by Flutter:

```bash
# Flutter 3.35 or newer
flutter create --org app.pagewatcher --project-name pagewatcher_mobile --platforms android,ios .
node tool/convert_i18n.mjs            # web locales -> lib/l10n/*.arb (already committed)
flutter pub get                       # also generates lib/l10n/gen/
flutter analyze && flutter test
```

`flutter create .` leaves existing files alone and only adds the missing platform scaffolding. Afterwards:

- **Android** (`android/app/build.gradle.kts`): set `minSdk = 23` (needed by flutter_secure_storage).
- **iOS** (`ios/Runner/Info.plist`):
  - Add the reversed iOS client ID as a URL scheme, plus `GIDClientID`, for Google sign-in.
  - Enable the *Sign in with Apple* capability in Xcode.
  - Set the deployment target to 13.0 or later.

## Running

```bash
# Against the local docker-compose backend from the Android emulator
flutter run --dart-define-from-file=env/dev.json

# Against production
flutter run --dart-define-from-file=env/prod.json
```

Configuration values are in `lib/core/config/env.dart`: `API_BASE_URL`, `WEB_BASE_URL`, `GOOGLE_SERVER_CLIENT_ID` and `GOOGLE_IOS_CLIENT_ID`.

## Translations

- UI strings come from the web app's i18next files (`common`, `app`, `auth` namespaces) and are converted to ARB by `tool/convert_i18n.mjs`.
  - Keys become camelCase with their namespace as a prefix, e.g. `auth.modal.signIn` becomes `l10n.authModalSignIn`.
  - `{{var}}` becomes a placeholder, and `_one`/`_other` keys become ICU plurals.
- Strings only the mobile app needs live in `i18n/mobile/<lang>.json` (prefix `mobile…`). English and Turkish exist so far; the other languages fall back to English.
- Re-run the converter after changing either source.

## Structure

```
lib/
  core/        config, network (dio + auth refresh), storage, router, theme, shared widgets
  features/
    auth/      data (repository, social sign-in, User), application (AuthController), ui
    settings/  ui
    shell/     bottom navigation + placeholder tabs
  l10n/        generated ARB files (gen/ is build output)
tool/          convert_i18n.mjs
```

State is managed with Riverpod, routing with go_router. Routing reacts to `AuthController`: signed-out users are sent to `/welcome` or `/login`, new sign-ups to `/trial`, everyone else to the tabs.

## Backend changes this app needs (in `../pagewatcher`)

1. **Apple sign-in audience.** The native iOS identity token has the app's bundle ID as its audience, not the web Services ID. `/auth/apple` has to accept both. See `APPLE_CLIENT_ID` in `backend/app/config.py` and `_verify_apple_id_token` in `backend/app/api/routes/auth.py`.
2. **Google** needs no change. The app passes the web client ID as `serverClientId`, so the tokens already have the audience the backend checks.
3. **Push notifications** (milestone 7): device-token table and endpoints, a `push` channel type, and an FCM sender.
4. **Deep links** (milestone 8): `apple-app-site-association` and `assetlinks.json` served from `pagewatcher.app`.
